Competition Details Screen - Functional Full-Stack Module COMPANY Feedants ROLE Full Stack Development Intern
Assignment
You are provided with a design reference for a Competition Details screen from Feedants.
Your task is to build this screen as a functional full-stack feature, not simply reproduce the UI.
The implementation should closely follow the provided design while functioning like a real competition page in a production application.
Required Technology Frontend React Native
Backend
Node.js + Express.js Database MongoDB
You are free to use any additional libraries, tools, technologies, architectural patterns, or services that you believe are appropriate.
Problem Statement
The information displayed on the Competition Details screen should be dynamic and served through the backend/database rather than being hardcoded in the application.
Features and information visible in the provided design should behave functionally wherever applicable.
Your implementation should account for situations such as:
•
Competition information and availability
•
User participation or registration state
•
Competition dates and lifecycle
•
Remaining participation spots
•
Time-dependent information
•
User actions based on the current competition state
•
Consistency of competition data when multiple users interact with the system
You are expected to determine the appropriate:
•
Frontend states
•
Backend logic
•
APIs
•
Database structure
•
Validations
•
Business rules
•
Edge cases

We intentionally do not provide a predefined API structure, database schema, or detailed implementation approach. Make the technical decisions you believe would be appropriate for a real-world, scalable application.

•

•
React Native implementation quality
•
Component structure and reusability
•
Dynamic handling of competition and user states
•
Backend architecture and API design
•
MongoDB data modelling
•
Correctness of business logic
•
Handling of validations and edge cases
•
Handling of concurrent user actions and data consistency
•
Scalability and production-readiness
•
Code quality, readability, and maintainability
•
Technical decisions and overall problem-solving approach Important: A solution that only reproduces the UI using static or hardcoded data will not be considered a complete submission.
We are interested not only in whether the feature works, but also in how you approach and structure the problem.

A short screen recording demonstrating the working implementation
README
